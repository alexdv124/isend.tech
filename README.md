# isend.tech

**Файлы, фото и текст между устройствами — в браузере, без установки и регистрации.**

[Открыть isend.tech](https://isend.tech) · [English](README.en.md) · [Развёртывание](docs/DEPLOYMENT.md) · [Архитектура и ограничения](docs/ARCHITECTURE.md)

Откройте сайт на телефоне и компьютере, выберите устройство и отправьте файл. Можно перетащить файл, вставить его через **Cmd+V / Ctrl+V**, передать текст или сделать фото на телефоне. Возможности вставки и камеры зависят от браузера.

Проект базируется в России; публичный сервис размещён в России. Исходники позволяют развернуть собственный экземпляр в другой стране.

## Что умеет

- **Находит устройства автоматически** по общему внешнему IP. Если мешает VPN или устройства в разных сетях — знакомство по четырём цифрам с подтверждением на втором устройстве. Код действует две минуты; попытки ограничиваются.
- **Запоминает знакомые браузеры**: после знакомства они могут находить друг друга и в разных сетях, включая VPN. Очистка данных браузера сбрасывает его идентификатор.
- **Готовит соединение заранее**, когда выбрано устройство. Для двух устройств это происходит автоматически; при большем числе первоначальный выбор — по алфавиту.
- **Выбирает маршрут автоматически**: WebRTC напрямую, когда это возможно, либо через настроенный TURN-ретранслятор. Маршрут и скорость видны в интерфейсе.
- **Передаёт содержимое без сохранения файлов на сервере**. TURN пересылает зашифрованный поток; сервер приложения обслуживает обнаружение и установку соединений.
- **Проверяет блоки SHA-256 и восстанавливает передачу после обрыва** в пределах возможностей выбранного способа сохранения.
- **Принимает большие файлы сразу в выбранный файл на диске** в поддерживаемых настольных браузерах. Это позволяет обойти квоту хранилища сайта.
- **Передаёт текст в обе стороны**, показывает имена устройств, предлагает мобильную камеру и удерживает экран включённым во время передачи, если браузер разрешает.
- Интерфейс на **русском и английском**, подробная диагностика и серверные инструменты статистики.

## Чем отличается

По сравнению с устанавливаемыми средствами вроде LocalSend, для начала работы достаточно открыть сайт. По сравнению с отправкой себе в мессенджер, не нужен вход в аккаунт на втором устройстве. Сочетание короткого знакомства, запоминания браузеров, предварительного соединения, передачи текста и сохранения на диск сокращает действия при повторном использовании.

WebRTC, TURN и браузерная передача сами по себе не уникальны. Это не обещание превосходства над каждым конкурентом по скорости или надёжности: результат зависит от браузеров и сети.

## Быстрый запуск

Нужны Node.js **22.13+** (рекомендуется 24 LTS) и npm.

```sh
git clone https://github.com/alexdv124/isend.tech.git
cd isend.tech
npm ci
npm run typecheck
npm run build
npm test
npm start
```

Откройте `http://127.0.0.1:8788`. Для теста на одном компьютере используйте **два разных профиля браузера** — например, обычное окно и инкогнито. Вкладки одного профиля используют общий идентификатор и не считаются разными устройствами.

Сервер слушает только loopback. Для доступа с телефона или другого компьютера нужен HTTPS через обратный прокси: [инструкция VPS и TURN](docs/DEPLOYMENT.md). Без TURN соединение между некоторыми сетями не установится. После новой сборки перезапустите сервер: он загружает статические файлы в память при старте.

## Большие файлы и докачка

| Способ приёма | Где находятся данные | Ограничения |
|---|---|---|
| Хранилище сайта (OPFS) | На устройстве получателя, под управлением браузера | Квота сайта; контрольные точки сохраняются в хранилище |
| Выбранный файл на диске | Через системный диалог сохранения | Нужен `showSaveFilePicker`, обычно настольные Chrome/Edge; докачка живёт в открытой вкладке |

В поддерживаемом браузере диалог выбора файла предлагается автоматически от **512 МиБ** или при нехватке квоты; можно включить его для всех файлов. Дождитесь завершения и закрытия потока записи. При закрытии или перезагрузке принимающей вкладки в этом режиме незавершённая запись не считается сохранённой, передачу потребуется начать снова. Для возобновления отправитель должен иметь доступ к исходному файлу.

Нет гарантии «любой размер в любом браузере»: остаются ограничения свободного места, файловой системы, API браузера и фонового выполнения. Не все браузеры смартфонов умеют прямую запись в выбранный файл. Подробнее: [архитектура](docs/ARCHITECTURE.md).

## Приватность

Содержимое файлов и текста передаётся по зашифрованному WebRTC-каналу, не через HTTP-хранилище приложения. Сервер видит служебные данные соединения; при включённой диагностике сохраняются обезличенные технические события, размеры, скорости и категории ошибок, но не имена файлов и не их содержимое. Пары браузеров также могут сохраняться на сервере.

Сервис не является анонимной сетью: веб-сервер, STUN/TURN и сетевые провайдеры могут видеть адреса соединений. Пользователь доверяет коду, который отдаёт сайт. Независимый аудит безопасности не проводился. [Подробности и эксплуатация](docs/OPERATIONS.md).

## Состав репозитория

- `app/` — React-интерфейс; `lib/` — передача, запись на диск, буфер текста, обнаружение и диагностика.
- `server.mjs` и соседние `.mjs` — HTTP-сервер, сигнализация, пары, журналы и аналитика.
- `public/storage-worker.js` — работа с OPFS в Worker.
- `tests/` — автоматические проверки протокола, хранения, сервера, пар и аналитики.
- `scripts/` — сборка и операторские отчёты; `deploy/` — примеры настроек VPS и TURN.

Это исходники клиента версии 28. Версия `/healthz` относится к серверу и может отличаться от версии клиента. Секреты, SSH-ключи, производственные конфигурации, пользовательские журналы и зависимости в репозиторий не включены.

## Проверки и участие

CI выполняет `npm ci`, проверку TypeScript, тесты и сборку. Тесты включают сценарии записи, отмены и восстановления больших файлов; модельный тест больших смещений не заменяет испытания многогигабайтного файла на реальном устройстве.

Для сообщения об ошибке укажите браузеры, версии страниц, маршрут, направление передачи и обезличенные показатели из «Сведений о передаче». Не публикуйте личные файлы, ссылки знакомства, ключи или необработанные журналы. Известные ограничения перечислены в [архитектуре](docs/ARCHITECTURE.md).

Отдельная лицензия на исходники пока не выбрана; публичная доступность репозитория сама по себе не предоставляет лицензию на распространение производных продуктов.
